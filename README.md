# Smart Rock-Paper-Scissors

和会读你行为模式的 AI 玩石头剪刀布。规则改了两次，但核心没变：**谁都在赌对方有没有骗你**。

## 玩法：双盲承诺

1. **宣告**：你先说要出什么（可以撒谎，也可以"不告诉你"）
2. **AI 回应**：它会说点什么——但**它的宣告被锁住了，你看不到**
3. **实际出拳**：看不到它宣告的情况下，选你真正出什么
4. **揭晓**：双方宣告一起亮，按实际出拳判胜负

关键在于信息不对称：**你说的话它听得见，它说的话你听不见**。

原本它会把自己的宣告直接告诉你——那等于玩家单方面透明，最优策略退化成"读宣告 → 反制"，博弈就塌了。现在你只能从它的只言片语里推测有没有被骗，而它同样在猜你会不会撒谎。

## 对手有三档

难度不是靠提示词里写"你是高手"实现的——那纯属自我感动。真正的四个杠杆：

| | 注入信息量 | 欺骗倾向 | 是否亮底牌 | 刻意误判率 |
|---|---|---|---|---|
| **新手机** | 近 5 轮原始结果 | 七成五诚实 | 从不 | 不适用 |
| **熟客** | 出拳分布 + 欺骗率 | 五五开 | 偶尔点一句 | 一成 |
| **读心者** | 条件模式 + 你对它的反应 | 七成欺骗 | 总是明说 | 两成半 |

几个设计上的要点：

- **最难的不是它更强，是它读得更准。** 读心者会明确说"你宣告石头的时候七成会出布，这次我不信了"——把暗中较劲变成显性心理对抗。
- **但它有保底弱点。** 当你的出拳分布足够均匀，读心者的规律分析会失效，它会在对话里承认自己跟不上了。**掺随机是对抗它最有效的办法。**
- **难度越高越要留错。** 读心者有 25% 的误判率——不然玩家无解，游戏也不成立。

统计上的两个阈值都经过模拟校准，不是拍脑袋定的：

- **样本量门槛 5 轮**：宣告只有 3 种，小窗口必然产生误报。模拟显示 10 轮窗口内某宣告出现 ≥5 次的概率高达 **62.6%**——门槛太低，读心者会把噪声当规律报出去，玩家一试就发现是假的，可信度就崩了，而可信度是这个人格唯一的武器。
- **随机化阈值 50%**：模拟 10 万次 30 轮三拳均匀随机，最大拳占比中位数是 40%、75 分位 46.7%、95 分位 53.3%。取 45% 会有约 40% 的真随机玩家被误判成"还在用规律"。

因此统计窗口（30 轮）与明细窗口（10 轮）**分开**：条件模式需要样本量才可靠，但把 30 轮明细全塞进上下文太贵。所以统计在 30 轮上进行、只把结论注入给模型，明细仍只给最近 10 轮。

## 我的画像

每轮结束会更新"对手眼中的你"：诚实度、出拳分布、以及**已被算出的规律**（红标为最危险的那条：你跟着 AI 宣告走的倾向）。

这个面板存在的理由是：**玩家看不见自己被读出了什么，就没有反制的动力。** 博弈退化成单方面被分析。

标红的规律可以刻意打乱——故意在宣告石头时改出布，规律就废了。

## 本地运行

零构建纯静态站：

```bash
node dev/static-server.mjs 8000
# 或任意静态服务器：npx serve . / python3 -m http.server
```

打开 `http://localhost:8000`，首次进入需要配置模型接入。

## 模型接入（自带 API key）

直接调用 **OpenAI 兼容的 `/chat/completions`**，开始界面选服务商即可：

| 服务商 | 默认模型 |
|---|---|
| DeepSeek | deepseek-chat |
| OpenAI | gpt-4o-mini |
| 智谱 GLM | glm-4-flash |
| Moonshot Kimi | moonshot-v1-8k |
| 自定义 | 任意 OpenAI 兼容端点（含本地 Ollama） |

**关于你的 API key**：

- key 只存在你浏览器的 localStorage，请求由浏览器**直连**你选择的服务商，不经过任何中间服务器
- 游戏没有后端，网络请求只有一处（`ai.js` 的 `chatCompletion`）
- 注意各家服务商对浏览器直连（CORS）的支持不同
- 不建议在公共电脑上使用

## 设计说明

**防作弊由调用时序保证，不靠 prompt 自觉。** AI 的宣告与实际出拳都在"玩家宣告之后"的那一次模型调用里锁定（游戏每轮只调一次模型），之后你出什么它都改不了——结构上不存在 AI 偷看的可能。双盲承诺改的只是**显示时机**（宣告藏到揭晓），不是调用时序。这条约束写在 `game.js` 头部注释里，改动前请想清楚。

**AI 回应格式异常时，绝不替 AI 出拳。** 系统解析模型输出的 `{"taunt", "declared", "actual"}`；任一字段缺失会自动重问一次，仍失败则明确报错、本轮作废。特别地，**宣告解析失败不会被伪装成"AI 选择保密"**——那会凭空抹掉唯一的博弈素材，而双方都察觉不到。解析走 JSON 主路径 + 正则兜底，不依赖 `response_format` 参数（各家服务商支持不一致）。

**AI 输出是不可信输入。** 所有模型返回的文本一律走 `textContent` 插入 DOM，不进 `innerHTML`；换行由 CSS `pre-wrap` 处理。见 `dev/test-parse.mjs` 与 `dev/e2e-check.mjs` 的 XSS 用例。

**对局记录持久化。** 比分和历史存在 localStorage，刷新不丢；"重新开局"一键清零。

## 本地开发

不想花 token？仓库带了一个本地 mock：

```bash
node dev/mock-server.mjs   # 跑在 http://localhost:8768/v1
```

设置里选"自定义"，base URL 填 `http://localhost:8768/v1`，key 随便填即可玩通全流程。模型名可切换行为：

| 模型名 | 行为 |
|---|---|
| （默认） | 合规 JSON，宣告与实际时一致时不一致 |
| `honest-model` | 宣告与实际一致 |
| `legacy-model` | 老格式纯文本，测正则兜底 |
| `fenced-model` | 代码块围栏 + 前后废话，测容错 |
| `bad-model` | JSON 缺 `declared`，测重问与报错 |
| `garbage-model` | 完全不解析，测游戏错误弹窗 |
| `xss-model` | `taunt` 里塞 HTML，测 XSS 防护 |

跑完整质量门禁：

```bash
sh dev/check.sh              # 全部 5 层，约 2 分钟
sh dev/check.sh --fast       # 跳过最慢的设计落地验证
```

门禁分五层：

| 层 | 内容 | 断言数 |
|---|---|---|
| 1 | ES module 语法检查 | 9 文件 |
| 2 | 解析器单元测试 | 25 |
| 3 | 博弈画像单元测试 | 30 |
| 4 | 端到端浏览器验证 | 21 |
| 5 | 设计落地验证（30 轮 × 三档难度） | 28 |

第 1 层为什么要复制成 `.mjs`：`node --check` 会把 ES module 当 CommonJS 解析，查不出对象字面量被误删这类语法错误（踩过：批量删代码时吃掉了 `ui.init({` 的开头，静态检查全绿但页面白屏）。第 5 层再拿真实浏览器加载兜一层。

> 第 5 层**只能验证"设计意图是否在代码里落地"**（难度杠杆是否真的产生不同注入、统计阈值是否真的生效、双盲是否 30 轮不泄漏），**不能验证 AI 的行为效果**——mock 的回复与上下文无关。要测效果需要真实模型 API。

生成界面截图：

```bash
node dev/mock-server.mjs &
node dev/static-server.mjs 8000 &
node dev/screenshot.mjs   # 输出到 docs/screenshots/
```

## 项目结构

```
├── index.html           # 页面结构、设置界面、难度选择
├── styles.css           # 样式
├── ai.js                # 模型接入：fetch 客户端、人格提示词、回应解析
├── profile.js           # 战绩统计与博弈画像（纯逻辑，无 DOM/网络）
├── game.js              # 状态机、规则、持久化、难度分级注入
├── ui.js                # DOM 渲染与事件绑定
├── images/              # 出拳图与表情包素材
└── dev/
    ├── mock-server.mjs      # 本地 mock
    ├── static-server.mjs    # 零依赖静态服务器
    ├── test-parse.mjs       # 解析器回归测试（25 项）
    ├── test-profile.mjs     # 博弈画像测试（30 项）
    ├── e2e-check.mjs        # 端到端浏览器验证（21 项）
    ├── verify-design.mjs    # 设计落地验证（28 项，30 轮 × 三档）
    ├── check.sh             # 全部质量门禁
    └── screenshot.mjs       # 界面截图
```
